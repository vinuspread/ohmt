# 카카오톡 링크 미리보기 OG 이미지 크롭 문제 해결 기록

## 증상

카카오톡 채널 채팅(웰컴 메시지)에서 링크를 공유하면, `og:image`로 지정한 1200×630 이미지가
정사각형에 가까운 형태로 **매우 좁게 크롭되어** 로고/텍스트가 잘려 보인다.

일반적으로 알려진 "OG 이미지 권장 사이즈(1200×630, 1.91:1)"나 "중앙 80% 안전영역" 가이드를
그대로 따라도 해결되지 않았다.

## 잘못된 가설들 (시간 순서대로 시도했지만 실패)

1. **캐시 문제라고 가정** → 카카오 OG 캐시 초기화 도구(`developers.kakao.com/tool/clear/og`)로
   캐시를 여러 번 초기화 → 실패.
2. **캐시 문제라고 재가정** → og:image 파일명을 두 번 변경(`og-image.png` → `og-image-v2.png` →
   `og-site.png`)해서 강제로 새 URL을 만듦 → 그래도 동일하게 잘림. **이걸로 캐시 문제가
   아니라는 게 확정됨** (파일명이 다르면 캐시가 있을 수 없다).
3. **로고를 "630×630 안전영역" 안에 재배치** (일반적인 OG 안전영역 가이드 기준) → 실패.
   → 이 시점에서 "카카오 채널 챗봇 카드는 일반적인 OG 크롭 규칙을 따르지 않는다"는 것을
   알아챘어야 했다.
4. **카카오 채널 관리자센터(center-pf.kakao.com)에 별도 썸네일이 등록되어 있을 것이라 가정**
   → 확인 결과 별도 이미지 없음, og:image를 그대로 쓰는 게 맞았음.

## 실제 원인을 찾은 방법: 스크린샷 픽셀 역산

말로 설명된 "잘린다"는 증상만으로는 원인을 알 수 없었다. 실제 카톡 채팅 스크린샷을 픽셀
단위로 분석해서 **카카오가 실제로 보여준 크롭 영역이 원본 이미지의 어느 좌표인지**를
역산했다.

방법:
1. 원본 이미지에서 알아볼 수 있는 랜드마크 2개 이상의 좌표를 특정한다 (예: 로고 브라켓의
   왼쪽 끝 x좌표, 특정 글자의 시작 x좌표).
2. 스크린샷(카톡 썸네일)에서 동일한 랜드마크가 위치한 픽셀 좌표를 잰다.
3. 두 좌표쌍으로 `스크린샷_좌표 = a * 원본_좌표 + b` 선형 매핑을 풀어서, 스크린샷의
   좌/우/상/하 끝이 원본 이미지의 어느 좌표에 대응하는지 역산한다.

결과: 카카오가 실제로 보여준 영역은 1200×630 원본 기준 **가로 약 300px, 세로 약 150px**
(2:1 비율), 그것도 캔버스 중앙이 아니라 **약간 왼쪽으로 치우친 위치**였다. 이전에 적용했던
"630×630 안전영역"은 목표 자체가 실제 크롭 크기보다 2배 이상 컸던 것.

```bash
# Python(PIL)으로 스크린샷/원본 이미지의 특정 좌표 색상을 뽑아 비교하는 방식으로 진행
python3 -c "
from PIL import Image
img = Image.open('screenshot.png').convert('RGB')
px = img.load()
for x in range(65, 510, 5):
    print(x, px[x, 480])
"
```

## 적용한 해결책

핵심 아이디어: **로고/텍스트가 담긴 컨테이너를 "고립된 뱃지"처럼 만들지 않으면서도, 실제로
읽혀야 하는 로고 자체는 훨씬 더 작고 정확히 중앙에 배치한다.**

1. 기존 로고 스프라이트(브라켓 + 워드마크)를 원본 이미지에서 그대로 잘라낸다 (폰트를
   다시 그리지 않고 실제 브랜드 아트웍을 재사용).
2. 원본에 있던 반투명 얼룩덜룩한 배경 밴드를, **전체 폭(1200px)에 걸친 단색 밴드**로
   교체한다 (사진마다 색이 달라 밴드가 균일하지 않던 것을 정리).
3. 로고 스프라이트를 약 50% 축소해서 밴드 정중앙에 붙여넣는다. 이때 스프라이트 가장자리에
   완전 불투명 → 완전 투명으로 이어지는 알파 페더(feather) 마스크를 적용해서 이음새가
   보이지 않게 한다.
4. 최종 결과를 1200×600 (정확한 2:1)로 상하 15px씩 크롭한다.
5. **새 파일명**으로 저장한다 (기존 파일은 삭제하지 않음 — 다른 곳에서 참조 중일 수 있고,
   비교/롤백 대비).
6. `openGraph.images`, `twitter.images`의 url/width/height를 새 파일로 갱신한다.

```python
from PIL import Image, ImageDraw, ImageFilter

img = Image.open("og-original.png").convert("RGB")
w, h = img.size

# 1) 로고 스프라이트 추출 (좌표는 실측값에 맞게 조정)
sprite = img.crop((sx0, sy0, sx1, sy1))

# 2) 전체 폭 단색 밴드로 교체
base = img.copy()
draw = ImageDraw.Draw(base)
draw.rectangle([0, band_y0, w, band_y1], fill=(24, 22, 20))

# 3) 스프라이트 축소 + 페더 마스크로 중앙에 합성
scale = 0.52
sprite_small = sprite.resize((int(sprite.width*scale), int(sprite.height*scale)), Image.LANCZOS)
mask = Image.new("L", sprite_small.size, 0)
ImageDraw.Draw(mask).rectangle([14, 14, sprite_small.width-14, sprite_small.height-14], fill=255)
mask = mask.filter(ImageFilter.GaussianBlur(14))
base.paste(sprite_small, (paste_x, paste_y), mask)

# 4) 정확한 2:1 비율로 크롭
final = base.crop((0, 15, 1200, 615))  # 1200x600
final.save("og-share.png", optimize=True)
```

## 체크리스트 (다른 프로젝트에서 같은 문제를 만났을 때)

- [ ] 정말 캐시 문제인지 먼저 의심하지 말 것. 파일명을 바꿔도 동일하게 재현되면 캐시가
      아니라 **크롭 로직 자체**가 원인이다.
- [ ] "1200×630 + 중앙 80% 안전영역"은 일반적인 OG 크롤러(Facebook/Twitter/Slack) 기준이지,
      **카카오톡 채널 챗봇 카드에는 적용되지 않을 수 있다.** 카카오 채널의 웰컴 메시지 카드는
      훨씬 더 좁은 영역(실측 기준 원본의 약 25% 폭, 25% 높이 수준)만 보여줄 수 있다.
- [ ] 말로 된 증상 설명("잘린다")만으로 안전영역을 추정하지 말고, **실제 캡처 스크린샷을
      픽셀 좌표로 역산**해서 정확한 크롭 비율/위치를 구한 뒤 그 기준으로 재설계한다.
- [ ] 카카오 채널 관리자센터(center-pf.kakao.com)에 썸네일이 별도로 등록되어 있는지도
      확인 대상에 포함할 것 (og:image와 무관하게 별도 이미지를 쓰는 채널 설정도 있다).
- [ ] Next.js에서 root `/` 경로에 봇 UA 감지 후 별도 메타데이터를 노출하는 로직이 있다면
      (리다이렉트 우회용), 그 파일도 og:image 갱신 대상에 반드시 포함할 것 — 실제로 카카오
      크롤러가 `/ko`가 아니라 이 루트 경로를 긁어갈 수 있다.
- [ ] 텍스트가 포함된 로고를 이미지 안에 넣어야 한다면, 로고를 원본 그대로 축소해서 재사용하고
      (폰트를 다시 그리지 않기), 배경은 "전체 폭 단색 밴드"처럼 크롭되어도 자연스러운 형태로
      유지해 "고립된 뱃지"처럼 보이지 않게 한다.
